## Cloudflare Tunnel による外部公開

ポート開放を行わず、Cloudflare Tunnel 経由でインターネットに公開しています。

**選定理由：**
- ルーターのポート開放が不要でセキュリティリスクを低減
- Cloudflare の DDoS 対策・SSL 証明書管理を無料で利用可能
- 自宅ネットワークの IP アドレスを外部に露出しない

## 開発・デプロイの経緯

Vercel / Render でのプロトタイプ開発から、Raspberry Pi を用いたセルフホスト環境での実用化まで、以下のステップを経て構築しました。

### 1. インフラ構築の経緯

- **選定理由**：最小単位での初期リリースを目指し、研究室の資産（Raspberry Pi）を活用してインフラコストを完全に無料化
- 初期は Vercel（フロントエンド）/ Render（バックエンド）で動作確認。実用化にあたりラズパイへ移行

### 2. 直面した課題と解決策

#### ① 環境変数の管理

- **課題**：Vercel からラズパイへ移行した際、バックエンドが正常に動作しない問題が発生
- **解決**：クラウド環境と同様に、サーバー側でも `.env` ファイルによる API キー管理が必要であることを確認し、環境変数の注入を徹底

#### ② API クォータ削減のための DB キャッシュ実装

- **課題**：外部 API（NAVITIME・Google Maps）の呼び出し回数に制限があり、リクエストのたびに計算するのが非効率だった
- **解決**：PostgreSQL を導入し、一度取得した駅間の所要時間・座標データを DB に保存するキャッシュ機構を実装。API 消費量を大幅に削減しつつレスポンスを高速化（詳細は [backend.md](./backend.md) 参照）

#### ③ Google OAuth の設定

- **課題**：初期実装時に Google Cloud Console の設定ミスにより「安全ではないページ」警告が表示される問題が発生
- **解決**：OAuth クライアントの承認済み JavaScript 生成元・リダイレクト URI を正確に定義し直してセキュリティ警告を解消

### インターネットの仕組み

#### ブラウザが Web ページを開く時に起きていること

```
┌──────────────┐   ①「example.com ってどこ？」   ┌─────────────────────┐
│ あなたの PC   │ ──────────────────────────────▶ │  DNS（電話帳）       │
│              │ ◀────────────────────────────── │  「93.184.216.34だよ」│
└──────────────┘   ②IP アドレスを教えてもらう      └─────────────────────┘
        │
        │ ③そのIPアドレスにアクセス！
        ▼
┌──────────────────────────┐
│  サーバー（93.184.216.34） │
│  「ページのデータを送るよ」 │
└──────────────────────────┘
        │
        │ ④データが返ってくる
        ▼
   Webページが表示される！
```

**DNS（Domain Name System）**：人間が読めるドメイン名 → コンピュータが使う IP アドレス に変換する仕組み。電話帳と同じ。

#### HTTP と HTTPS の違い

| プロトコル | 暗号化 | 安全性 |
|-----------|--------|--------|
| `http://` | なし | 盗聴できてしまう |
| `https://` | あり（SSL/TLS） | 安全・今の標準 |

### Nginx（エンジンエックス）の役割

```
                   ┌─────────────────────────────────────────┐
                   │            ラズパイの中                   │
                   │                                          │
  ブラウザ          │  ┌─────────┐       ┌──────────────────┐ │
  ─────────────────┼─▶│  Nginx  │──────▶│  /var/www/html/  │ │
  「ページください」  │  │（店員）  │       │  index.html など  │ │
  ◀────────────────┼──│         │◀──────│  （コンテンツ）    │ │
  「はいどうぞ」     │  └─────────┘       └──────────────────┘ │
                   └─────────────────────────────────────────┘
```

Nginx を入れると「サーバーとしての仕事」ができるようになる。
リクエストを受け取り → ファイルを探して → データを返す。

### なぜ家のラズパイに外からアクセスできないのか

#### 家のネットワーク構造

```
     インターネット
          │
          ▼
  ┌──────────────┐
  │   ルーター    │  ← 外向きの IP アドレスを 1 つだけ持つ
  └──────────────┘
     │        │
     ▼        ▼
 ┌────────┐ ┌────────┐
 │ラズパイ│ │  PC   │  ← 192.168.x.x（プライベート IP）
 └────────┘ └────────┘
     家の中だけで有効な住所
```

`192.168.x.x` は**プライベート IP アドレス**。外のインターネットからは直接届かない。  
→ これが「外からアクセスできない」理由。

#### 普通の解決策（ポートフォワーディング）の問題点

ルーターの設定で「外からの通信をラズパイに転送」することもできるが…

- セキュリティリスクが高い（家の IP が外部に丸見え）
- プロバイダによっては使えない
- 設定が難しい

---

### Cloudflare Tunnel が解決する仕組み

#### 通常 vs Cloudflare Tunnel の経路比較

```
【通常のポート開放（今回は使わない）】

 外部ユーザー ──▶ インターネット ──▶ ルーター ──✖── ラズパイ
                                           ↑
                                      ここで止まる

──────────────────────────────────────────────────────────

【Cloudflare Tunnel を使った経路（今回の方法）】

                              ┌────────────────────────────────────┐
                              │           ラズパイの中               │
  外部ユーザー                 │  ┌──────────────┐   ┌────────┐    │
      │                      │  │  cloudflared  │──▶│ Nginx  │    │
      ▼                      │  │（トンネルソフト）│   └────────┘    │
 ┌──────────────┐  トンネル   │  └──────┬───────┘                 │
 │  Cloudflare  │◀──────────┼─────────┘                          │
 │  のサーバー   │            │   ラズパイ側から接続を開始する！      │
 └──────────────┘            └────────────────────────────────────┘
      ▲
      │
 外部ユーザーのリクエストを
 Cloudflare が受け取り転送
```

**ポイント：ラズパイ側から接続を開始している！**

1. ラズパイが自分から Cloudflare に「トンネル（専用通路）」を張る
2. 外のユーザーがドメインにアクセス → Cloudflare がトンネル経由でラズパイに転送
3. ラズパイの Nginx が応答してページを返す

→ **ルーターに穴を開けなくていい！**

#### Cloudflare が盾になってくれる理由

```
                     ┌─────────────────────────────────┐
  悪意のあるアクセス   │           Cloudflare              │
  DDoS 攻撃    ──✖──▶│  ・DDoS 攻撃をブロック             │
  不正リクエスト ──✖──▶│  ・HTTPS を自動で適用             │──▶  ラズパイ
                     │  ・怪しいアクセスをフィルタリング   │  （安全！）
  正常なアクセス ──────▶│                                 │
                     └─────────────────────────────────┘
```

### 全体の通信フロー（完成後）

```
①  ブラウザに practice.circlemanage.jp と入力
           │
           ▼
②  DNS が「Cloudflare のIP アドレス」を返す
           │
           ▼
③  Cloudflare のサーバーにリクエストが届く
           │
           ▼
④  Cloudflare が事前に張られたトンネルを通じてラズパイに転送
           │
           ▼
⑤  ラズパイの cloudflared が Nginx にリクエストを渡す
           │
           ▼
⑥  Nginx が Web ページのデータを返す
           │
           ▼
⑦  逆の経路でユーザーのブラウザに届く
           │
           ▼
      Web ページが表示される！
```
